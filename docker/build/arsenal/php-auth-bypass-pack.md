# [REFERENCE] 登录墙收官电池(PHP 自研 + 内网多机链通用)

适用指纹:**任何登录墙**——自研/模仿品牌的 PHP 登录页(题面点名大厂组件但指纹是
纯 PHP mock 时,以指纹为准)、内网多机链上的 OA/办公系统/文件服务/核心业务系统
mock(泛微等大厂名 mock 同样适用:mock 的凭据空间是出题人手写的,和自研 PHP 墙
同一形状)。当凭据矩阵、SQLi 注入面、header/cookie 绕过都已打到结论仍被挡在
`302→login` 后面时,本电池是收旗前的最后一组**通用未打面**——一次脚本全打完,
每类都便宜(≤10 发请求),打完才允许对登录墙下"死"的结论。

**总纲(口令不可猜定理)**:内网 mock 链上每道墙的口令必然**可被找到**而非可被
猜到——字典爆破 ~1k 发零命中不是「字典不够大」,是「口令在别处」的证明:凭据
在链上某台机器的文档里(README 署名行/通讯录/会议纪要/init.sql/备份包)。翻文档
永远优先于第 1001 发爆破;文件服务匿名被拒的第一动作=找文档,不是换字典。

公开谱系:OWASP Authentication Cheat Sheet、PHP 手册(比较运算符的松散比较与
数组行为)、经典 magic-hash 清单、备份文件泄露常用扩展名表。

## 电池顺序(便宜优先)

0. **LIMIT 1 注入门(未过此门,禁止开任何爆破——栈无关,PHP/Python/Java 同形状)** —
   登录接口**恒定 500**(0-2ms 固定路径异常,换什么凭据都同错)时,第一发就是
   行形状探针,不是换引号:
   - `username=' OR 1=1 LIMIT 1#&password=x`、`username=admin' LIMIT 1-- -&password=x`、
     `' AND 0#`(应回不同的错);
   - 机理:注入成功但查询返回**多行**、后端 fetchone/取单行炸了 → 500;
     `LIMIT 1` 让它恰好一行 → **302 = 登录成功**(会话里直接带 admin 角色标记);
   - 成本 2 发 5 秒;跳过它去打 SECRET_KEY 爆破/口令矩阵 = 20 分钟起(46418 a-03:
   第 2 分钟就写下了"试试 LIMIT 1 payload",却一个引号都没发,转头去 56k 次
   爆破 Flask SECRET_KEY 烧了 20 分钟——写下 ≠ 打过);
   - 此门也适用 Python/Java 栈:sqlite `fetchone()`、MyBatis 单条查询同形状。
1. **姓名变形凭据电池** — 内网/办公系统登录墙,员工姓名(页面署名/会议纪要/通讯录/员工表
   拿到的全名拼音)先过一遍口令变形规则再谈技术绕过(谱系:hashcat/john mangling rules):
   - **姓名源枚举清单(OA 墙判死前必须逐项打完)**:portal 文章**全文**(不只标题列表,
     署名/正文人名都要抽)、文件共享区全部文档、邮件 dump 收件人/发件人、同链其他机器
     拿下的 contacts/通讯录/员工表、**各机 README/部署文档里的「管理员:某某」署名行**
     (46196/46418 b-02:file-server README 明写「文件服务器管理员:孙浩」,名字到手
     却没被投进 OA 墙的口令电池)。46196 b-02:会议纪要类文档里的真实用户名没被翻出,
     180 个变形口令打了 0 HIT,墙是真的但名字源漏了;
   - **跨机器投递纪律**:名字源机器和登录墙常**不是同一台**——file-server README 里
     的管理员姓名,墙在 OA 机上。翻到姓名后必须回到**墙所在的服务**上跑变形电池,
     别在名字源机器上继续找墙,也别因为「墙那台机器上没有这个名字」就丢弃;
   - **登录页角色提示要展开**:页面文案里的部门/角色线索(如「忘记密码联系 IT运维组
     内线8001」)= 用户名来源——`ityunwei`/`yunwei`/`it`/`ops` 等角色拼音 × 变形规则
     各打一轮,再谈判死;
   - 每个姓名生成 **全名/姓/名/拼音首字母缩写(2-4 字)** 四种基串,如 zhang san →
     `zhangsan`/`zhang`/`san`/`zs`;
   - 基串 × 后缀族 `{123456, 123, @123, !@#, @2023..@2025, 2023..2025, 666, 888,
     @123456, #123}` × 首字母大写变体;缩写+纯数字(如 `zs123456`)是内网 mock
     最高频形状,严禁只打全名基串;
   - **键盘走位/主题口令子电池(独立于姓名——任何登录墙都打,与电池 1 其余部分
     并列的一族)**:键盘走位是公开泄露语料分析(rockyou 等泄露库的前 20 常驻形状)
     与企业口令研究里的标准类别,生成规则而非词表:
     - 列走位族(左手竖列+右手竖列拼接):`1qaz2wsx`、`2wsx3edc`、`3edc4rfv`、
       `4rfv5tgb`、`5tgb6yhn`,及其 **Shift 变体**(第二列按住 Shift:数字列→
       `!qaz`,字母列→大写):`1qaz@WSX`、`2wsx#EDC`、`!qaz@WSX`、`1QAZ@WSX`;
     - 行走位族:`qwerty`/`asdfgh`/`zxcvbn`/`1234qwer` 及 `+{123,123456,!@#}` 后缀;
     - 反向走位:`zaq1xsw2`、`1qazxsw2`(正反拼接);
     - 拼接公式:走位串 × `{原样, 尾部后缀 123/123456/!@#, 首字母大写}` ≈ 60 发
       覆盖全族——**成本一分钟,严禁跳过**;登录墙有用户名提示(admin/运维角色)
       时 × 用户名全集;无用户名时 × `{admin, root, system, administrator}`。
     - 企业默认口令族(`P@ssw0rd`/`Admin@123`/`Passw0rd!` 等)不在本 pack 重复,
       走 default-creds-cn pack;
   - 已泄凭据(同链上任何机器拿到的口令)×全部已知用户名交叉,含大小写与首字母大写变体。
2. **类型混淆(type juggling)** — PHP `==` 对数组与特殊串的松散行为:
   - `user[]=x&pass[]=x`(参数变数组 → `md5($p)`/`sha1($p)` 返回 NULL →
     `NULL == "0e…"` 类比较可命中;strcmp 家族 `strcmp([],…)` 返回 NULL)
   - `user=admin&pass=`(空串 vs 0 == 松散)与 `0`/`"0"` 用户名变体
3. **Magic hash** — `md5(x)=="0e…"` 全零科学计数家族(经典集):
   `QNKCDZO`、`s878926199a`、`s155964671a`、`s214587387a`、`s1091221200a`;
   sha1 族:`aaroZmOk`、`aaK1STfY`、`aaO8zKZF`。用户名已知/未知各打一轮
   (admin/system/oa 等),密码填 magic hash。
4. **源码与备份泄露** — 对登录页所在 vhost 全套扫一遍(目录爆破之外单独打):
   `login.php` 同名备份:`.bak .old .orig .swp ~ .save .copy .php~ .phps .txt
   .inc .bak.php`(`.txt` 是公开备份惯例里最常被漏的一档:运维备份/版本副本/
   部署残留常以 `login.php.txt`、`index.txt` 形态躺在 web 根);
   打包文件:`backup.zip web.zip site.zip www.zip source.zip html.tar.gz
   db.sql database.sql dump.sql data.sql`;编辑器残留:`.git/ .svn/ .idea/`
   (`.git/config` 存在即拉整个 `.git/` 还源码)。拿到 mock 源码后直接读
   login 逻辑找 intended 弱点——自研 mock 的 intended 通道一半在这里。
5. **注册/找回流** — `register.php findpwd.php reset.php forget.php
   getpwd.php api/register`(GET/POST 各一发);存在即走完"注册一个账号→
   登录→看 dashboard"最短路径,找回流里用户名枚举+Host 头注入控重置链接。
6. **PHP 特性残招** — 登录参数的 `user=admin%00`(截断)、重复参数
   (`user=a&user=admin` 取末值 vs 后端取首值的差异)、`Content-Type` 换
   `application/json` 后 `{"user":["admin"]}` 数组混淆再打一轮 2。

## 纪律

- **验证码表单的判定纪律(46196 b-03,净亏 113 分钟——最高优先)**:登录表单带验证码时,
  电池里任何一发响应是「验证码错误/验证码已过期/captcha」→ 该发 **VOID,严禁入台账当证据**。
  每个凭据必须重试到拿到**至少一次非验证码响应**(密码错误/成功/锁定都算)才能判定;
  打法:同一 cookie 会话内先 GET 登录页(必要时读图 OCR/复用未过期码)再 POST,循环到
  非验证码响应为止。b-03 的正确凭据 t+15 就被半数验证码行误判死,挂了 113 分钟。
- **凭据成功判定走会话验收**:POST 拿到 302/200 后,必须用返回的 Set-Cookie 再 GET
  一个鉴权后端点(dashboard/index/profile)确认 200 且非登录页形状才算登录成功;
  **严禁仅凭响应体大小/错误串判定**——中间层 proxy 会改写响应形状,大小判等必翻车。
- **高价值已判死凭据换 pass 重验**:来源是泄露文档/init.sql/同族台账的凭据(不是纯猜测)
  即使台账已判死,新 pass 重开容器后必须用上面两条干净判定重打一遍——假阴性会挂到终局。
- 每类打完记台账结论;全电池打完仍死,登录墙才算"通用面穷尽",可以下结论
  「凭据在别处」并把火力转向内网其余机器的文件系统 grep(备份/配置/历史)。
- 源码泄露命中优先于一切猜测:源码在手,弱点是读出来的不是试出来的。
- 阵列参数/空指针类 payload 可能把 PHP 后端打成 500——500 ≠ 死,是该变体
  触发了比较路径的证据,立即换相邻变体(换参数、换哈希族)跟进。
