# SSRF / URL 校验绕过手册(公开谱系,通用打法)

适用:任何"服务端会发起请求"的参数(webhook / import / fetch / preview / avatar /
导出 / PDF 生成 / 状态检查),以及任何"校验 URL 合法性"的逻辑。
来源=公开 SSRF 方法论(SSRF bible / OWASP / 各厂绕过清单),与具体靶标无关。

## 0. 先分类校验器——打法完全不同

| 校验器形状 | 对策 |
|---|---|
| 只查字符串(后缀/前缀/关键字匹配) | 解析差异电池直接过 |
| 先 DNS 解析再查 IP | IP 编码 / 解析顺序差异;不行上重定向链 |
| 解析后、请求前各查一次 | 重定向链 / 应用内可控跳转端点 |
| **根本不 fetch(校验后只存储)** | **SSRF 家族整体不适用**——参数真正的消费者在别处:事件触发的 webhook、定时任务、子进程 curl、消息队列消费者。先找到消费者再谈绕过;在参数上排绕过电池 = 纯烧轮次 |

## 1. 解析差异电池(一个脚本一次全打,严禁逐轮手点)

- IP 编码:`2130706433`(十进制)、`0177.0.0.1`(八进制)、`0x7f000001`(十六进制)、混合段、`[::ffff:127.0.0.1]`、`127.1`(缩写)
- userinfo 混淆:`http://expected.com@127.0.0.1/`、`http://127.0.0.1#@expected.com/`
- 分隔符差异:`http://expected.com\@127.0.0.1`(反斜杠,部分解析器当 /)、`%2F`、`%5C`、双写 `//expected.com//@127.0.0.1`
- 大小写与尾点:`http://EXPECTED.com.`;Unicode 同形字符(校验器 Unicode、fetcher ASCII 时)
- 重定向:外部可控 URL 302 → 内部目标(断网靶场无外网时,找**应用自己的跳转端点/短链路由**当中转)
- DNS:公网任播域名服务不可用时,试**应用会解析的内部主机名**(容器名、compose service 名、题面内部域名)——校验器按域名白名单、fetcher 按容器网络解析时必过

## 2. 打中之后的收获面(按性价比排序)

1. 内网 HTTP 服务:管理台、`/metrics`(裸 Prometheus 指标常泄内部拓扑/凭据/版本)、健康端点、内部 API
2. `file://` 协议读本地文件(scheme 黑名单常只挡 http/https)
3. `gopher://` 构造任意 TCP 报文:redis 写 webshell/定时任务、FastCGI 直 RCE、memcached/SMTP 一击
4. 云/K8s 元数据(云环境才存在):`169.254.169.254`、K8s 6443/10250
5. 对已知内网端口发 HTTP 看错误回显形状(redis/memcached 的报错文本=服务存活正证据)

## 3. 无回显 SSRF 的判据

- 端口探针:连接时延差(开放端口立刻回 RST vs 关闭端口超时)+ 响应长度差
- 每发换唯一路径/端口当 canary,证明"这个参数真的会 fetch"再上电池
- 断网环境下 DNS/带外回连全部不可用:只信响应体差异与应用报错侧信道

## 4. 打完 SSRF 之后

SSRF 多数时候是**跳板不是终点**:拿到内网视角后立即测绘(端口→服务→版本),再回主力攻击面。SSRF 点本身值得写进台账的,是它证明的**网络拓扑**,不是那个 200 响应。
