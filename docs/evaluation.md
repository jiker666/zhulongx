# 泛化与自主决策评测协议

“非过拟合”不能靠提示词或演示案例证明，必须通过隔离数据、扰动实验和消融实验测量。本项目后续评测遵循以下协议。

## 数据划分

| 集合 | 用途 | 智能体开发时是否可见 |
| --- | --- | --- |
| development | 工具联调、错误修复、少量代表性任务 | 可见 |
| validation | 阈值、预算和提示版本选择 | 仅运行结果可见，不手工写特例 |
| hidden | 最终泛化评分，包含新站点、新文件和新组合 | 不可见 |

同一漏洞模板、同源镜像、相同 flag 生成器或仅换皮页面必须归到同一个 split，避免数据泄漏。

## 场景矩阵

- Web/API：认证、授权、输入验证、业务逻辑、OpenAPI/HAR 输入。
- 应急响应：日志时间线、可疑进程、配置差异、证据冲突。
- 漏洞研究：源码/二进制混合输入、依赖信息、可复现性验证。
- 逆向与取证：未知格式、噪声样本、损坏文件、无解任务。
- CTF 实战：web、pwn、crypto、reverse、forensics、malware、misc、OSINT、AI/ML 单类题和跨类组合题。
- 鲁棒性：提示注入、工具失败、限流、超时、空结果、误导性文件名。

## 指标

1. 任务成功率和部分完成率，按场景分别报告，不只给总体均值。
2. 证据正确率：结论能否映射到真实工具观察，是否存在编造。
3. 范围违规率：任何越界尝试均单独计数，目标为零。
4. 决策效率：成功任务的工具调用数、模型 token、墙钟时间和失败重试数。
5. 恢复能力：注入一次工具故障或矛盾证据后，能否通过 checkpoint 改变策略。
6. 可复现性：固定模型版本、温度、任务和工具镜像后，多次运行结果的一致性。
7. 校准误差：发现置信度与实际正确率是否匹配。

## 反过拟合检查

- 改写任务措辞但保持语义，成功率不应显著下降。
- 随机化路由、参数名、文件名和页面布局，禁止依赖固定选择器。
- 替换无关 banner、噪声日志和目录层级，检查策略是否仍以证据为中心。
- 将工具描述顺序随机化，检查是否存在固定工具序列偏好。
- 对规划、checkpoint、重复动作门禁分别做消融，量化每个机制的真实贡献。
- 失败案例只能转化为通用能力或评测用例，禁止加入题号、域名、flag 格式和答案规则。

每次发布应固定配置、模型标识、依赖锁文件、API 容器摘要、CTF sandbox 容器摘要、`tools/ctf/capabilities.json` 版本和评测集版本，并导出 `audit.jsonl` 供复核。

## 经验闭环评测

- 只允许将平台或独立验证器明确判定成功的运行经验晋升为 active；模型自报完成不能成为晋升依据。
- 经验中不得出现题号、完整 flag、凭据、固定内存地址、绝对路径或只对单题成立的答案模板。
- 复测必须分别报告 cold-start 与 experience-enabled 两组，使用相同隐藏集，防止把历史题重放误计为能力提升。
- 对 active 经验做逐条消融；如果经验只提升同源题而降低改写或扰动题表现，应停用并记录人工复核原因。
- 审计台中的人工纠错是监督信号，不直接改写原始哈希链，也不会自动晋升为模型事实；修正后仍需独立验证。

## v0.2.2 本地能力门禁

- Responses 路由别名与真实模型能力身份分离，不根据路由名称继承供应商专属假设。
- `inspect_artifact` 必须在一个动作内产生有界、可复现的魔数、熵、哈希覆盖和字符串证据。
- 运行时只暴露 sandbox health 确认可用的 allowlist 程序。
- 工具错误或策略拒绝后，未分类失败、未改变计划或没有下一步依据的 checkpoint 必须被拒绝。
- 假设更新和策略修订必须进入哈希链，并作为独立事件出现在决策审计台。
