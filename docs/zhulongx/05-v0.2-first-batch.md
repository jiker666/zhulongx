# zhulongx v0.2 技术实施方案 — 第一批

依据:六轮实测轨迹 41762(28)→41925(53)→42176(54)→42298(DOA,基础设施 bug)→42314(16@2.4h 中止)→42361(**52/63**,错 flag 全场 1 次,hints 16 次)。
原则:全部是引擎/存储/提示词局部改动,**不加新架构**;benchmark 反作弊红线不变(镜像内零题号知识,一切走通用教条)。

## 0. 现状盘点(合并版分析的事实修正)

| 合并版声称 | 源码事实 | 结论 |
|---|---|---|
| run --deadline / 时间预算缺失 | `RunDeadline`(350m)、`GoalWallBudget`(30m)、`GoalStepBudget`(6)全在(engine.go:283-315);步超时已被剩余墙预算封顶(execute.go:76-95) | **已建成**。缺的是"剩余时钟注入提示词"与"末段收尾纪律"(见 W3a) |
| MaxConcurrentSteps=2 单值 | 单值结构属实,managed.yaml 实际为 4;StepGate 已按目标门控(容器槽) | 半成立,优先级降为第三批 |
| Conclude 超时打捞缺失 | JSON 契约修复轮已存在(repairJSON);**超时路径**才是缺口:adapter 超时 → abort → Close 杀进程 → `return nil, ErrTimeout`,已积累的 streamText 全部丢弃(adapter.go:139-157) | **真缺口**(W3c) |
| Fact 无分层、上下文无预算 | 属实:renderGraphSection 把**全部** facts+steps+findings 塞进每一发 decide/execute 提示词(render.go:72-95),无截断、无去重、无预算 | **真缺口**(W1,第一批最大件) |
| 派发前健康检查缺失 | launchRunner 有 SpawnRetries,但系统性故障(网关挂)每次都烧一个 attempt | **真缺口**(W3d,用断路器而非主动 ping) |

六轮数据里的对应病灶:
- **W1**:42176 c-03 单题 10 轮 execute、70 万 in-token——图越滚越大,每轮全量重读;inject-facts 单条 6.2KB 环境纪律 fact 每发提示词都全文携带;a-18 拉满 4 hint 后,4 条 hint+全部晋升事实每轮重复进上下文。
- **W3a**:42361 末段 a-14/a-16/c-03 在剩余时间不足时仍按"完整 pass"节奏推进,模型不知道全局时钟。
- **W3b**:63 题每题先付一轮 decide 分解税(20-70s 串行),easy 层多数题一发直解就出——合计 20-70 分钟纯排队。
- **W3c**:execute 超时 → failStep(retryable) → 从零重跑同一 step;台账(work.md)虽在,但图内零沉淀,decide 看不到部分产出。
- **W3d**:42298 类基础设施死亡会在多步上连烧 attempts 配额;网关抖动期(42314 requeue churn)同理。

## 1. W1 上下文工程 + Fact 分层

### 1.1 schema v2(最小迁移)

新文件 `internal/store/migrate.go`:

```go
var migrations = []struct {
    version int
    stmts   []string
}{
    {2, []string{
        `ALTER TABLE facts ADD COLUMN title TEXT NOT NULL DEFAULT ''`,
        `ALTER TABLE facts ADD COLUMN kind TEXT NOT NULL DEFAULT ''`,
        `ALTER TABLE findings ADD COLUMN title TEXT NOT NULL DEFAULT ''`,
        `ALTER TABLE findings ADD COLUMN kind TEXT NOT NULL DEFAULT ''`,
    }},
}

func migrate(db *sql.DB) error // 读 meta.schema_version,按序逐条 Exec,事务包裹,写回版本号
```

- `Open()`(store.go:135)在 schemaV1 之后调用 `migrate`。旧库无感升级;`kind=''` 视为 legacy。
- kind 词表:`seed`(引擎/pass 种子)| `env`(环境纪律)| `recon` | `result` | `verdict` | `flag` | `blocker`。空=legacy,按 result 处理。
- `fgs.Fact`/`fgs.Finding` 增加 `Title string`、`Kind string`(fgs/types.go);晋升时 store 拷贝(findings.go ReviewFindings)。

### 1.2 契约变更(internal/contract)

`ExecuteAnswer` 增加 `Title`、`Kind`(validate.go:45)。`ValidateExecute`:
- `finding.title` 可选,≤120 rune,缺省取 content 首行前 60 rune;
- `finding.kind` 可选,枚举校验,非法值拒绝(吃一次修复轮);
- `evidence` 接受 string **或 object**(`{commands:[{cmd,exit,key_output}], artifacts:[{path,sha256}], repro:"..."}`),object 规范化为缩进 JSON 字符串存库——证据台账(W2)的载体,不另加列。

execute.md 输出示例同步更新(title/kind 一行说明,evidence 优先结构化)。

### 1.3 预算化组装(internal/prompt/assemble.go,新)

```go
type AsmBudget struct {
    MaxGraphRunes int // 0 = 不限量(旧行为,回退开关)
    FactFull      int // 非钉住 fact 全文渲染条数(按新近度,默认 12)
    DoneSteps     int // done step 单行渲染条数(默认 6)
    EvidenceRunes int // 每条 open finding 的 evidence 截断(默认 700)
}
func AssembleGraph(g *store.Graph, b AsmBudget) string
```

替换 render.go:72 的 `renderGraphSection`,decide 与 execute 共用。分层规则:

1. **钉住层**(永远全文):objective/origin;kind∈{seed,env} 的 fact;全部 hints(hint 是花钱买的,永不禁缩)。
2. **事实层**:非钉住 fact 按时间倒序,前 `FactFull` 条全文;更早的渲染成 `- f_0007: (verdict, 摘由) <title>` 单行。**近似去重**:非钉住 fact 与已渲染 fact 前 80 rune 相同时,渲染为 `(dup of f_0007) <title>`。
3. **步骤层**:open 全文;done 尾部 `DoneSteps` 条单行;更早的只留计数 `(+14 done, elided)`。
4. **发现层**:open 全文 + evidence 截断至 `EvidenceRunes`;已决(promoted/discarded)只留计数。
5. 总量超 `MaxGraphRunes` 时从**最老的非钉住层**开始降级(全文→单行→计数),钉住层永不降级。

配置(managed.yaml):`runtime.context_budget: 9000`(rune 计数,免 tokenizer 依赖;CJK 友好)。cfg.Runtime 加 `ContextBudget int`。

### 1.4 测试

- migrate:v1 库 fixture(手工构造)升级后 title/kind 可写可读,版本号=2,二次 Open 幂等。
- contract:title/kind 缺省、超长、非法枚举、evidence object→规范化 JSON。
- assemble:预算内全文;超预算按层降级且钉住层存活;dup 折叠;open finding evidence 截断;`MaxGraphRunes=0` 退化为旧输出(golden 对比)。
- render golden:decide/execute 提示词快照,防意外膨胀。

## 2. W2 证据台账 + 晋升前机械验证

### 2.1 结构化证据(承载于 1.2 的 evidence object)

execute.md 规则增补:凡声称**可复现**的结果(拿到会话、注入成立、RCE 落地),evidence 必须带 `repro`(一条可重放命令)与 `artifacts`(落盘路径+sha256)。台账文件 attack/<题号>/work.md 已是既成事实的落盘层,artifacts 指向它即可。

### 2.2 晋升验证钩子(引擎接口先行,实现后置)

```go
// engine.Engine 新增(与 StepGate/NoopRescue 同款的接线风格)
VerifyPromotion func(ctx context.Context, f *fgs.Finding) (ok bool, note string)
```

decide.go 晋升路径:对 `answer.Promote` 逐条过钩子;不过者**留在 open**,note 经新 store 方法 `AppendFindingNote(goalID, id, note)` 追加到 content 尾部(下轮 decide 可见"验证未过:原因"),并写 audit 行 `finding.verify_failed`。钩子为 nil(默认、benchmark 接线)时行为与今天完全一致。

- **benchmark 不接**:平台判分(answer_correct/wrong)就是外部真值,SlotGate 已观测;机械复验无增量。
- **通用形态第二批复用**:ReproVerifier(沙箱内重放 evidence.repro,exit/key_output 比对)。接口先进第一排,防将来改签名。

### 2.3 测试

- 钩子拦下指定 finding:留 open、note 追加、audit 落行、其余正常晋升。
- nil 钩子全通过(回归)。
- AppendFindingNote 对非 open finding 报 ErrFindingNotOpen。

## 3. W3 执行经济学四件套

### 3a 剩余时钟注入(时间经济学)

```go
// internal/prompt/clock.go
type RunClock struct {
    RunElapsed, RunRemaining time.Duration
    GoalPass                 int // 1..3
    GoalWallUsed, GoalWall   time.Duration
    GoalStepsDone, GoalStepB int
}
```

- RenderDecide/RenderExecute 增参,渲染 `### Run clock` 块(decide.md/execute.md 模板各加一段占位)。
- 附一条通用纪律(非题号知识):`RunRemaining < 20%` → 只做"最便宜的未测动作"与收尾;`< 10%` → 冲洗台账、有唯一重推导候选才再交一次。
- engine 填充:scheduleGoal/decide/executeStep 组装(GoalPass 取 `requeues[title]+1`)。
- 测试:RunClock 渲染快照;时钟注入不改变既有替换占位(golden)。

### 3b Bootstrap 直解步(免分解税)

- cfg.Runtime 加 `BootstrapStep string`(默认空=关闭;benchmark 的 managed.yaml 置为直解指令模板,如"直接进攻本题:读题面与台账,一发完成侦察+攻击+flag 提交,仅在报告里建议分解")。
- scheduleGoal:目标**零步骤且无快照**时,`CreateStep(goalID, 模板渲染(objective), nil, "engine:bootstrap")`,跳过首轮 decide。
- decideTrigger 的 `initial` 改为仅"无任何步骤"时触发——bootstrap 步存在则等首个 finding(facts/findings 增长触发本就覆盖),decide 首轮即带真实战果复盘。
- 测试:bootstrap 开启 → 创建步+不跑 decide;关闭 → 旧行为;bootstrap 步 done 后 decide 正常接管。

### 3c 超时打捞(adapter + execute)

- adapter.Prompt 超时分支(adapter.go:143):Close 之前抓取 `streamText/toolCalls/events` 快照,返回 `(&PromptResult{Text: streamed, ToolCalls: n, Events: ev}, ErrTimeout)`——签名不变,调用方以 `res != nil` 判部分产出。
- executeStep `ErrTimeout` 分支:
  1. `res.Text` 里能 ExtractJSONObject + ValidateExecute 通过 → 走正常 FinishStepWithFinding( deadline 恰好在报告吐出后到点,今天这种情况整单作废);
  2. 否则 `FinishStepWithFinding(content="TIMEOUT_PARTIAL: <streamText 尾 400 rune>", evidence="events: ...")` → **step done 而非 failed**,不烧 attempt,部分产出进图,decide 可据此续作;
  3. `res == nil`(进程死/协议错)才走 failStep。
- 测试:mock runner 注入"超时但已流式输出 JSON"→ finding 正常落库;超时无 JSON → TIMEOUT_PARTIAL finding、attempts 不增;进程退出 → 旧失败路径。

### 3d 派发断路器(健康检查的零成本形态)

- engine 加 `failStreak int`、`cooldownUntil time.Time`;计数点:launchRunner 失败、`ErrProcessExit`(不含 ErrTimeout——那是慢,不是病)。
- streak ≥ 3 → cooldown 3 分钟:scheduleGoal 直接 return(steps 留 pending,零 attempt、零模型轮)。成功一步即清零。
- 主动 ping(一次模型往返)不做——断路器被动探测覆盖同类故障且零开销;留给第二排按需评估。
- 测试:连三败后 tick 不 claim、不 decide;cooldown 到期恢复;成功重置。

## 4. 实施顺序与验收

**验收门槛**:

- 行为(mockpi 63 题仿真):easy 层每题 decide 轮 ≤1(bootstrap 生效);超时步 ≥80% 产出 TIMEOUT_PARTIAL 而非 attempt 重跑;断路器注入三连败后零 claim。
- 跑分(下轮托管,对照 42361 基线):解出 ≥54;总 hints ≤12;错 flag ≤1;单题 in-token 峰值(42176 c-03 型)不复现。

## 5. 风险与回退

- **W1 截断过狠丢关键证据** → 钉住层+hint 永不降级;`context_budget: 0` 一键回退旧行为;golden 测试锁形状。
- **W3b 直解步在真多阶段题上浪费一发 execute** → 35m 内有墙预算封顶,且 execute.md 台账纪律保证产出不丢;managed.yaml 可关。
- **W3c 把烂尾输出当 finding 污染图** → TIMEOUT_PARTIAL 前缀让 decide 一眼可辨,descard 即可;audit 全程留痕。
- **迁移锁死旧库** → 事务+幂等;v1 fixture 回归测试;失败即整体回滚(单文件 SQLite)。
