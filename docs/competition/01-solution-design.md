# 方案设计文档

## 1. 目标与范围

烛龙·玄枢是面向授权网络安全任务的自主决策智能体运行时。它处理自然语言任务及文本、JSON/YAML/HAR/CSV、目录、ZIP、图像和二进制附件，要求模型先理解目标、提出计划和假设，再在证据、权限、预算和停止条件的约束下选择下一步动作。

设计目标不是让模型获得无边界执行权，而是实现可复核的闭环：

```text
任务理解 -> 计划与假设 -> 策略门禁 -> 受控工具执行 -> 证据与 checkpoint
    ^                                                               |
    +------------------- 失败分类与计划修订 -------------------------+
```

本项目不面向未授权扫描或无人值守生产攻击。模型不能直接访问网络、执行 shell 或扩大作用域；主动网络、浏览器、TCP 和受控命令均须经过策略层。

## 2. 总体架构

| 层次 | 主要组件 | 职责 |
| --- | --- | --- |
| 输入层 | `input.ts`、附件工作区 | 归一化任务材料、限制输入体积、建立只读输入目录 |
| 决策层 | `runtime.ts`、系统提示、计划/假设/检查点 | 驱动任务生命周期、根据公开证据选择下一步、在失败后修订计划 |
| 策略层 | `PolicyEngine`、预算与 Permission Gate | 核验主机、端口、路径、程序、动作次数、输出与时长；拒绝越权请求 |
| 执行层 | `tools.ts`、sandbox、HTTP/TCP/Browser | 以有界输入输出执行已授权的观察或动作；阻塞操作接受 `AbortSignal` |
| 证据层 | finding、checkpoint、共享证据板 | 记录可验证证据、置信度、失败分类与跨 agent 受限协作信息 |
| 审计层 | `audit.jsonl`、轨迹投影、前端 | 以 SHA-256 前向哈希记录公开上下文、策略判定和工具因果关系，并生成面向初学者的行动解释 |

运行事实以追加式 `audit.jsonl` 为中心。事件记录来源、执行者、关联 ID 与父序号；`tool.requested`、`policy.decision`、`tool.result` 使用同一调用 ID 关联。系统不持久化模型密钥、Authorization、Cookie、图片像素或隐藏推理。

## 3. 自主决策机制

1. `submit_plan` 是调查动作的前置条件，计划包含目标、成功标准、假设和候选工具。
2. 每次工具调用先由 `PolicyEngine` 检查 operator-owned scope 与预算；模型没有绕过入口。
3. 工具输出有上限，可能阻塞的工作接收 `AbortSignal`；超时、人工停止或预算用尽可中止执行。
4. 连续动作达到阈值时，策略只允许 checkpoint 类动作，要求总结证据并调整计划。
5. 重复工具和相同参数被拒绝，工具失败会被分类并触发计划修订，而非无变化重试。
6. 结论需要 evidence、置信度和完成/阻塞状态；Arena 场景的提交还需要独立验证闸门。

## 4. 多场景工具协同

核心循环保持领域无关。题型识别仅决定加载哪一类受审查的策略索引，工具权限仍来自统一注册表和策略层。当前源码提供 Web、密码、杂项、二进制/逆向、取证和其他材料分析方向的能力入口；每个方向使用同一计划、权限、预算、证据、审计和恢复契约。

二进制方向新增了两类本地有界能力：

- `extract_archive`：仅解压 ZIP 到本次运行 scratch，限制 500 个条目和 32 MiB，拒绝路径穿越与符号链接。
- `search_artifact`：在不超过 16 MiB 的文件前缀内执行 UTF-8 或十六进制字节搜索，匹配数、模式和上下文均受限。

完整 sandbox 工具链包含固定版本的 Radare2、JADX、Pwntools、`gdb-multiarch`、`ltrace` 与 binutils 辅助程序。它们只能经结构化 `run_command` 调用，仍受程序白名单、输出、超时、重复动作和 checkpoint 门禁约束。

## 5. 安全与鲁棒性设计

| 风险 | 设计控制 |
| --- | --- |
| 作用域扩张 | operator 配置定义权限；每次运行 scope 只能收窄 |
| 模型误判 | 模型仅提出请求；策略和工具注册表在执行前强制核验 |
| 无效循环 | 重复动作拒绝、动作预算与 checkpoint 强制收敛 |
| 命令与文件风险 | sidecar 使用结构化程序与参数执行，不经 shell；每 run 独立 scratch |
| 网络风险 | 仅 HTTP/TCP/Browser 工具可访问网络，且必须通过 `PolicyEngine` |
| 证据不可追溯 | 哈希链审计、请求-决策-结果关联、人工复核与可回放投影 |
| 敏感信息泄露 | 凭据从环境变量读取；审计与 transcript 脱敏并排除隐藏推理 |

## 6. 评分标准对应

| 评分维度 | 设计对应 |
| --- | --- |
| 任务理解与执行设计 | 多格式输入、计划/假设、动态工具选择、失败后修订 |
| 系统架构与工程实现 | 分层运行时、策略层、sidecar、结构化工具协议、前后端审计台 |
| 决策逻辑与可解释性 | 追加式审计链、证据引用、原因/影响/结果/下一步投影、回放与分叉 |
| 工具协同与扩展能力 | 统一工具目录、策略测试与副作用文档、领域策略索引、受限共享证据板 |
| 创新与附加价值 | 把自主性置于工程约束中；用同一事件流服务审计、回放、恢复与分支 |
