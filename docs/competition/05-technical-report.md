# 技术报告

## 摘要

烛龙·玄枢面向授权网络安全任务构建自主决策智能体运行时。系统将大模型定位为任务理解、计划、假设生成和行动选择组件，同时以 `PolicyEngine`、operator-owned scope、预算、结构化工具协议、隔离 scratch 和追加式审计链定义不可由模型绕过的工程边界。该设计旨在解决开放安全任务中“能否自主调整”与“能否安全、可解释地执行”同时成立的问题。

本次版本补充了面向二进制、逆向和 PWN 工作流的受限材料能力与 sandbox 工具链，并在审计台中将相关动作投影为可读事件。实现不把任何题目 ID、站点选择器、固定 Flag 或答案模板写入核心循环。

## 1. 问题与方法

网络安全任务常同时包含自然语言目标、日志、压缩文件、接口文档、源代码、二进制样本和网络交互。固定脚本难以处理输入变化和失败恢复，纯对话模型又无法承担安全边界。系统采用“模型负责判断，策略负责约束，工具负责执行，证据负责验证，审计负责追溯”的分工：

- 模型输出计划和结构化工具请求；
- 策略层逐次判定主机、端口、路径、程序、预算与停止条件；
- 执行层返回有界结果并支持取消；
- 证据和 checkpoint 驱动计划修订；
- 追加事件流支撑解释、回放、恢复和分支。

## 2. 核心技术

### 2.1 受约束自主决策

运行必须先提交计划。每次调查动作都消耗预算，并在达到节奏阈值时被强制 checkpoint。重复调用、越权调用和无效扩权会被拒绝；超时、空结果、策略拒绝和矛盾证据被分类后，智能体需要重新说明下一步行动依据。该机制将“自主”限定为受证据与授权约束的规划和调整，而非任意执行。

### 2.2 单一追加式轨迹

系统以哈希链 `audit.jsonl` 作为运行事实源，记录公开系统提示、公开模型上下文摘要、工具请求、策略结果、工具结果、子 Agent 调度和上下文注入的来源关系。运行恢复、轨迹回放与分支共用同一事件流；未知副作用的旧调用绝不自动重放。为保护安全和隐私，隐藏思维链、模型 Key、授权头、Cookie 和图片像素不写入产物。

前端将同一事实投影为面向初学者的决策流：用户可以看到 agent 正在做什么、依据是什么、产生什么影响、得到什么结果以及下一步准备如何变化，并可按事件来源筛选和检索。

### 2.3 可扩展的受控工具协议

工具由统一目录定义，并绑定策略规则、预算、审计事件和副作用说明。新增工具不通过提示词获得信任，必须具备 TypeBox 模式、有界输出、`AbortSignal`、确定性策略/预算测试与文档。主动网络始终由 scope 控制；本地命令通过 sidecar 结构化执行，不经 shell。

本次二进制扩展包括：ZIP 有界解压、UTF-8/十六进制有界字节搜索，以及 Radare2、JADX、Pwntools、`gdb-multiarch`、`ltrace` 等离线工具的固定版本和构建期完整性检查。归档工具限制条目数和解压总量，拒绝路径穿越与链接；搜索工具限制扫描前缀、模式、匹配数与上下文。所有调用均进入同一策略和审计链。

### 2.4 协同、恢复与评测

同题多 agent 可使用有界、脱敏的共享证据板，但每个 agent 保持独立 scratch，且必须独立复核共享结论。持久 Agent 和 Workflow DAG 使用租约、generation、effect 调度、预算聚合与 no-replay。评测账本可固定模型、环境、依赖、数据集、预算和轨迹引用，避免用单次演示替代可复现的测量。

## 3. 工程验证

本次整理后执行的默认工程门禁为 `npm run check`，结果为 typecheck、lint、测试和后端构建通过；测试记录为 390 passed、1 skipped（现有可选浏览器测试）。前端生产构建 `npm --prefix frontend run build` 通过。该结果说明当前代码在确定性回归与构建层面可交付，但不等同于真实模型或比赛平台上的成功率。具体测试范围见 [03-test-report.md](03-test-report.md)。

## 4. 创新性与价值

1. **约束优先的自主性**：自主规划不等于扩大权限，模型与策略边界明确分离。
2. **轨迹即事实源**：同一追加事件流同时服务审计、初学者解释、搜索、回放、恢复与分支，减少多套日志不一致。
3. **可治理的工具扩展**：工具扩展以策略测试、预算、审计与副作用文档为交付门槛，而不是简单加入命令。
4. **跨材料与跨方向统一**：文本、归档、二进制和网络观察接入同一任务闭环；二进制分析能力不改变核心循环的领域中立性。
5. **人机协同可复核**：队员保留授权确认、风险判断与最终决策，agent 提供连续分析和留痕证据。

## 5. 局限与后续工作

当前版本仍不应被视为无人值守生产扫描器。仓库已经明确记录的后续工程方向包括 DNS 解析锁定、统一出口代理、跨实例持久事件总线、租户级 microVM 隔离，以及在主办方仿真平台上进行长期、可复现实战评测。所有效果指标必须以固定环境、授权范围和脱敏轨迹为依据单独报告。

## 6. 结论

烛龙·玄枢将安全智能体的关键矛盾转化为可工程化验证的协议：模型可以理解、计划、选择和修订，但不能越过策略、范围、预算、隔离和审计。通过追加式轨迹、可读决策流和受控工具目录，系统为多场景安全任务提供了可解释、可扩展、可复现的自主决策底座。
